Architecture Note

Dynamic Multi-Tenancy Engine

In ed-idp, tenants do not require separate database clusters or heavy virtual host duplication. Instead, incoming HTTP requests are resolved dynamically via the URL path prefix (/t/{tenantId}/**) or tenant identification headers, and propagated across execution chains using Java 25 ScopedValue (TenantContext).

Path Scoped Issuer
Each tenant has an isolated OpenID Connect metadata discovery endpoint at /t/{tenantId}/.well-known/openid-configuration.
Isolated Cryptographic Keys
JWT signature tokens are signed and verified against tenant-partitioned JWK sets to prevent cross-realm forgery.
Partitioned Persistence
Registered clients, token grants, user profiles, and authorization consents strictly enforce tenant ID constraints.
